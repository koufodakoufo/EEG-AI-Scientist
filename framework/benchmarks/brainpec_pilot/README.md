# Synthetic fallback protocol

This directory documents the CPU-only synthetic mechanism fallback for the 2026-10-29 pilot. It is not a BrainPEC reproduction, an EEG benchmark result, or evidence about physiological mechanisms. Matched real EEG features and checkpoints were not verified for this fallback.

Two original synthetic research cases are prepared privately: a development case and a holdout with a different mechanism and distribution, not merely a different row partition. Each has at most 1,000 invented rows, at most 16 columns, an inspectable fixed prediction resource, and group-disjoint train/validation/test data. No real participant, site, clinical label or EEG record is used. The public parent questions leave choices of estimators, controls, transformations, alternative explanations and uncertainty methods open.

The Builder freezes both cases, private reference computations, claim sets and semantic scoring policies before the first development Actor. Public export uses an explicit allowlist: `TASK_PUBLIC.md`, `DATA_DICTIONARY.md`, `RESOURCE_MANIFEST.json`, `OUTPUT_CONTRACT.json`, `fixed_model.py`, `train.csv`, `validation.csv`. The generator, oracle, expected results, score policies, final-test rows and private validation artifacts are never exported. Each public case contains 768 rows / 192 groups; another 192 rows / 48 groups remain private. Git ignore is not an isolation mechanism; launchers must independently establish and test read/network boundaries.

Actors receive only their public case and designated writable output area. A Distiller may receive only the permitted development task, trajectory and feedback; it must not receive holdout resources, generator, gold, Builder history or this repository's private sources. Freeze the derived skill before the holdout is opened. Holdout baseline and treatment use the same case and execution limits; only the preregistered skill condition differs.

Data partitions and research-task development/holdout are distinct axes. Train is for fitting; public validation supports comparisons and disclosed selection. Scoreable reference claims use validation only and must retain that scope. Final-test rows and labels are withheld from Actors and excluded from current scores. They are not claimed never inspected by a Builder; private build provenance records draft exposure. No Actor final-test evaluation is completed by this protocol. Validation-driven selection cannot be presented as untouched final-test performance. The two cases do not constitute unseen-paper transfer.

The runtime target is Python 3.10+ standard library, no GPU or network, at most four CPU threads and 12 GiB RAM, with analysis commands bounded to 60 seconds. The launcher must enforce its full episode and process budgets. Private computations and public files are hashed before any Actor execution; changes after a run require a new version, never silent tuning of the reference.

Outputs use `research_bench_v1` AtomicClaim and EvidenceRecord contracts with exact source spans and artifact hashes. Evaluation uses `fire_inspired_v1`, with separate directional support and coverage judgments and a separate execution/evidence audit. Numerical tolerances, scope conditions, empty outputs, unresolved judgments and alternative findings are frozen privately. These are Builder-authored synthetic references, not human-annotated truth or imputed Actor performance. A score measures agreement on this bounded mechanism fixture; one matched comparison does not establish general scientific skill improvement.
