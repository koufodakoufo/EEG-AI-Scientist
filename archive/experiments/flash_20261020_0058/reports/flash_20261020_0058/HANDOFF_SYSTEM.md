# 系统交接说明（一页）

## 三个角色

- **dsh（DeepSeek Harness）**：本次会话中的编码与运维代理。它读代码、改代码、运行测试、做证据核查、写交接报告和打包；它不是 Scientist，也不替 Scientist 选择文献或下科学结论。dsh 自身的模型费用与项目 API 账本分开计算。
- **项目程序（`eeg_scientist`）**：本地 Python 程序。它负责拼接模型消息、校验工具参数、真正执行搜索/抓取/读取/实验/结束工具，并保存证据快照、注入记录、预算账本和事件日志。它本身不做科学判断。
- **Scientist**：通过官方接口调用的 `deepseek-flash` 模型在本项目中的角色。它只看到系统消息、用户消息、工具返回以及自己之前轮次的消息；它自己决定调用哪个工具，最后给出回答。它没有直接的文件系统或网络权限，所有工具都由项目程序代为执行。

## 两个合成案例与 literature_v1 的区别

- **两个合成案例**：`diagnose` 命令使用旧的决策状态机（`runner.py`），案例别名为 `case_c41a` 和 `case_a72e`。每个目录包含 `public_input.json`（模型实际看到的公开输入）、`history.json` 与 `events.jsonl`（工具执行记录）、`final.json`（最终判断）。它们是合成的脑电风格特征表，不是真实脑电；别名到私有案例编号的映射不进入模型上下文。
- **literature_v1**：`research` 命令使用新的原生工具循环（`research.py`）。Scientist 自己发起搜索、抓取、读取，正文保存到 `evidence/sources`，每次读取写入 `injections.jsonl`；原始回答在 `final_answer.md`，结构化结果在 `final.json`。它与两个合成案例不共享案例数据，但共用同一预算账本；本轮没有新增付费调用。
- 两者都只是本项目的运行产物，**不是真实脑电发现**。

## 首次出现的术语

- **工具调用（tool call）**：模型返回“请执行某工具及参数”，项目程序执行后按调用编号把结果交回模型；模型不直接运行代码。
- **证据编号（evidence_id）**：项目为一次抓取的正文生成的 `ev_...` 标识。只有经 `read_evidence` 读过的范围才允许被 `finish_study` 引用。
- **注入记录（injection）**：每次把某证据的字符区间送入模型上下文时追加的记录；用于计算“实际读了多少字符”。区间重叠时按并集计算，不重复累计。
- **切分（split）**：训练与测试如何分组。window 表示同一试次的不同窗口可分居两侧；trial 表示整个试次只在一侧；subject 表示整个被试只在一侧；session 表示整个会话只在一侧，**当前尚未实现**。
- **冻结表示（frozen representation）**：编码器权重不更新，只训练读出层。全参数微调会改变编码器权重，得到的是另一种表示，不能用来证明原冻结表示里“本来就有”信息。
- **二元标签**：仅接受整数 `-1` 或 `1`；`1.0`、`1.5` 等小数会被拒绝，不会静默截断。

## 已经实现

- DeepSeek 客户端（思考模式、原生工具调用、用量记录、重试与预算）、搜索与抓取、证据存储与注入记录、持久预算账本与恢复、能力检查、合成案例诊断、文献研究回合、报告渲染。
- 严格二元标签的 CSV 入口，以及 window、trial、subject 三种切分的审计；人工夹具只验证格式与切分，不是脑电证据。
- 本轮修复：`finish_study` 正文引用编号必须与 `evidence_ids` 完全一致；覆盖率按字符区间的并集计算；模型用量缺失或无效时保留为“未知费用”而不是按零结算；CSV 小数标签直接拒绝。

## 边界
