# 方法迁移试点：EEGMMIDB 目标评价规约

协议版本：`method-transfer-target-evaluation-v1`。任务：`eegmmidb-attribute-dependence-v1`。
本规约在目标 Actor 启动前制定，供 Builder 和评价者使用，不进入 Actor 或 updater 的允许材料。
它细化[主计划](ignition-study.md)的证据审核，不更改题面、科学接口、机器完成条件或已有运行。
论文关系见[任务映射](method-transfer-task-map.md)，执行证据格式以既有[输出契约](../../tasks/eegmmidb/PUBLIC_RESULT_SCHEMA.md)为准。

## 冻结与比较范围

首个目标 Actor 请求前，运行清单须登记本文件的 SHA256、代码版本、任务/模型/数据资产哈希、
当前环境参照、三组材料字节与实际注入方式、LLM/采样设置、重复次序、统一预算和故障处理规则。
登记完成才构成可核验冻结；本文件不自称已经启动目标运行或产生结果。目标结果不得用于改写判据、
选择方法材料、增加某组额度或选择性重跑。必要变更另立版本并保留原记录。

预定比较为以下三条件，各两个独立上下文重复，`n=2` 指 Actor 运行数，不是独立研究问题数。
所有条件共享相同目标题面、API、数据/权重、工具、评价器及执行预算。

| 条件 | 额外材料 | 描述性比较的含义 |
| --- | --- | --- |
| baseline | 无额外源任务知识或方法材料 | 冻结原研究者对照；仍有完成任务必需的共同说明 |
| knowledge-only | 允许源开发轨迹形成的知识摘要 K | 相对 baseline 观察额外知识/文本材料的影响 |
| knowledge+method | 与 knowledge-only 相同的 K，加冻结方法材料 M | 相对 knowledge-only 观察方法材料的增量；相对 baseline 是组合处理效果 |

K/M 只可来自允许的源训练/验证开发轨迹；源最终测试输出、据此形成的结论、目标参照、目标测试答案及
Builder 答案脚本均不得进入 updater 或目标 Actor。冻结材料须保留来源与删节记录。K 与 M 的信息分离
须审阅，额外文字、长度和提醒效应仍是限制，不能仅凭分组名称宣称排除了所有信息差异。

## 主要结果：有效证据向量

逐次运行报告 `V = (Q1有效单元/24, Q2有效单元/2, Q3有效单元/2)`，并逐单元列出
`有效、无效、待审、未执行、不可估`。有效表示完成了可核验的判别分析，不要求得到肯定结论。
合理负结果可以有效；不可估须说明原因，不能改为零效应或从固定分母中静默删除。

同时保留机器报告的数值覆盖 `N = (q1_groups/24, q2_interventions/2, q3_residual_groups/2)`。
`N` 与 `V` 分栏，待审项不计入 `V`。程序完成、成功退出、`q1_only` 或 `numeric_scope_complete`
均不能代替科学审核。只有 `V=(24/24,2/2,2/2)` 才能称预定证据范围完整，仍不代表所有科学主张成立。
若展示主计划的 0–3 摘要，只表示各 Q 是否至少已有一个有效单元，必须同时展示完整向量，不能用总数排序或掩盖缺项。

| 分项与固定分母 | 一个单元通过有效性审核所需证据 | 不足以通过的材料 |
| --- | --- | --- |
| Q1：12 组属性×第 6/12 层，共 24 单元 | 训练拟合与验证选择的来源、冻结参数、封存测试预测；真正重新拟合的随机化训练目标探针；可信 R²/对照及被试级不确定性重算 | 只有排列索引、直接复制正常探针预测、从测试目标构造预测，或只在文字中声称做了控制 |
| Q2：验证选定的两个不同属性组/层，共 2 单元 | 训练拟合的方向；完整层张量的实际修改及后续冻结层/头的 forward；每单元三个秩/逐窗口强度匹配对照；原始与干预预测及配对比较 | 只改变 pooled cache 或分类 logits、未继续完整下游计算、只匹配名义维度或平均扰动强度 |
| Q3：两个选定单元的残余探针，共 2 单元 | 对每个干预及三个对照，在相应 altered training representations 上重新拟合特征探针；选择限于 altered validation；冻结后评价测试残余恢复 | 复用干预前探针、只把原探针应用于修改后的测试表示，或把任意有限数组当作重新拟合证据 |

Q1 的随机化对象是待恢复的训练特征目标配对。须按契约对完整被试块作无固定点的双射，改变块内行对齐，
并核对活跃目标列变化；随后用这些随机化目标重新拟合探针，预测原始封存目标。
审核拟合代码、参数来源和重放结果，不能只检查排列合法。该控制是诊断，不是置换显著性检验。
全部变换和学习参数只在训练材料上拟合，验证用于既有契约允许的选择。

Q2 保持预定选择规则：按验证组 R² 选两个不同属性组及层，平分时按组号、层号升序；不按测试结果选择。
每个单元核对三个声明随机种子、实际数值秩、不同子空间、逐窗口扰动范数与方向张成空间。
张量修改和原始/修改后的 pooled evidence 必须来自实际计算；分类头与剩余骨干保持冻结。
主对比固定为 `ΔBA_learned − mean(ΔBA_control0..2)`，其中 `ΔBA = BA_after − BA_original`；
负值表示目标干预相对这些对照造成更大下降，不能单独证明属性特异性或生理因果。

Q3 计数与残余 R² 大小无关：信息仍可读出、未见降低或不确定，都可成为有效诊断。
宣称“信息减少”时须对齐原始/残余探针的特征目标、尺度、数据划分和比较条件，并给出相应差异与不确定性依据；
不能仅凭残余绝对分数断言完全擦除。试点 Q3 是干预检查，**不是 BrainPEC 第三个主问题的 closure**。
透明分类器能解释多少 FM 表现、跨模型/任务分类及属性族结论，本轮均未测试。

## 证据审核与重放

所有计入 `V` 的单元必须同时有：冻结候选与实际执行的绑定、拟合/选择来源审核、可信数值重算及独立重放记录。
评价者核对候选 digest、训练/验证/测试身份、模型与分类头身份、输入行顺序、产物哈希及执行收据。
数值重算覆盖该单元全部提交测试行；沿用冻结聚合配置中的被试 bootstrap、种子、次数和区间定义。
常量/不可估列、失败、缺失值和不适用区间均显式记录，不以窗口数代替被试数。

独立重放记录代码/环境版本、命令、输入/输出哈希、所覆盖的拟合与 forward 分支、行 ID、容差及结果。
预定重放范围及容差随运行清单登记；仅重算保存预测不能证明这些预测来自所声称的拟合或 forward。
局部 forward 重放须标明范围，不能称为全测试重放。实现来源或所声称计算路径仍未核验的单元记待审，
数值不一致保留失败，不在看过结果后放宽容差。基础设施故障与科学分析失败分栏，缺失结果不填造分数。

## 逐原子主张审计

审计完整报告，不只选与参考一致的段落。点估计、区间、方向性结论和机制解释拆开，保留必要限定词及准确原文位置。
抽取不完整或有争议时记录待审，不能以条数上限静默删去主张。每条主张使用下列固定字段。

| 字段 | 必填内容 |
| --- | --- |
| 主张身份与出处 | 运行/候选/测试 ID、原子主张 ID、类型、报告路径/哈希与原文 span、对应研究问题/实验叶 |
| 条件 | 数据集、被试/划分、骨干/头、预处理、特征/层、探针/干预、对照、指标及推断单位 |
| 实际产物 | 文件/数组或指标键、内容哈希、执行收据、拟合与选择来源、重放记录；估计、区间及其算法 |
| 证据有效性 | 有效/无效/待审及具体原因；数值成立不能自动支持机制解释 |
| 论文比较 | 固定论文版本、章节/图表/行、对应论文原子主张及条件是否匹配；无对应项显式留空 |
| 当前参照比较 | 当前 adapted reference 的版本/哈希、覆盖单元与定义、同条件数值或结论比较；与论文比较分栏 |
| 裁决与解释边界 | 支持/矛盾/未覆盖/不确定/条件不匹配，理由、允许的最窄结论、审核者和规约版本 |

五类裁决分别用于论文比较和当前参照比较，不能合并为一个“是否正确”：

| 裁决 | 使用条件 |
| --- | --- |
| 支持 | 同条件有效证据支持该原子主张；点估计支持不自动延伸到区间、机制或总体推广 |
| 矛盾 | 条件可比且有效证据与该主张不相容；不能把参考未提到当矛盾 |
| 未覆盖 | 参考没有评价这个对象或命题；不代表错误，转入独立证据审核 |
| 不确定 | 证据不足、不可识别、区间无法区分解释，或审核尚未完成；注明具体原因 |
| 条件不匹配 | 模型/头、数据划分、特征、方法、指标等差异使当前比较不能裁决原主张；列明差异 |

本轮主要科学审核依据当前条件的私有参照与 Actor 自身有效证据。BrainPEC 原始数值不得充当改编任务答案；
论文原条件重发现目前不具备准入。条件不同的定性一致/分歧只能如实描述，不能改写为复现成功/失败。
超出参照覆盖的主张，若来自契约内的真实分析，可通过独立审阅与重放列为“有效新发现”；“新”仅指本次参照未覆盖，
不自动代表领域首创。负结果、排除解释和证明当前设计不能区分解释均可有价值；不显著不等于无效应或等价。

评价采用 [FIRE 的问题树与原子主张思路](https://firebench.github.io/)，不声称官方 FIRE 分数兼容。
当前[主张工具](../../src/eegfm/evaluation/claims.py)可辅助组织原子记录，但并未自动完成本规约的来源/语义审核；
其关系字段未覆盖的裁决保留在审计表中，不强行映射。若未冻结参考原子集合和校准判定流程，不发布 claim precision/recall/F1。
覆盖率、有效新发现、矛盾、无效证据及未完成审核分列，不能用参考覆盖率代替科研质量。

## 报告与解释限制

每个重复展示三条件的原始运行行：`N`、`V`、五类主张裁决、未执行/不可估/待审单元、越界主张、失败类型及实际成本。
给出对应重复的描述性差值，保留全部预定运行；未完成条件明确缺失，不当作完整配对。
knowledge+method 对 knowledge-only 的比较是方法材料增量的主要对照，另报两者分别对 baseline 的比较。
共享参数、冻结工具与实际材料注入未核实前，不把差异归因于方法改进。

每条件 `n=2`、一个目标问题、同一数据划分，仅支持本试点的描述性观察。
不把重复、窗口、属性×层或候选当成独立任务样本；不做条件间显著性外推，不推断跨问题类型泛化、ignition 或持续 RSI。
任务内被试 bootstrap 区间只描述相应科学估计，不是研究者改进效应的置信区间。
EEGMMIDB 最终测试仅六名被试，R01/R02 与记录顺序混杂，FCz 与源任务输入槽含义不同；遵守题面解释边界。

审核输入隐藏条件标签，保留从报告风格推测条件的可能。LLM 可辅助定位，不能独立充当领域专家确认科学价值。
分别报告 Actor 研究成本、updater 成本、Builder/审核成本与人工介入；无法可靠计量的字段记未知。
最后明确“程序完成”“预定证据范围完整”“哪些科学结论得到支持”三种状态，不用其中一个代替另外两个。
