## 1. 项目究竟要让什么变好

cx（陈翔）的构想明确区分两个产物：内环产生 EEG 科学知识，外环产生更好的研究者。内环应自主建立观察、提出竞争解释、选择可区分解释的实验、执行、修正结论；外环从失败、负结果和有限专家反馈中更新研究方法，再到新问题检验。

因此，BrainPEC 式“信息是否可恢复、是否影响预测、是否只是一般损坏”是一类有用任务，不能成为整个项目的定义。更广的任务包括跨被试泛化、表示与读出瓶颈、数据价值、预训练目标与数据交互、适配策略和负迁移。

cx 原文第 15–18 节已经提出两项关键要求：改进后的 Scientist 更善于产生下一代；在相同反馈下比较不同更新机制，并设置 knowledge-only 对照。下一阶段应把这两点变成可执行协议，而不是只增加一个经验文件。

建议把主张分成四级，避免不同论文的 Level 编号混用：

| 主张 | 必须观察到的证据 | 不能代替该证据的现象 |
| --- | --- | --- |
| 能自主做研究 | 实际完成假设、实验、证据与解释闭环 | Builder 参考脚本完成、报告写得完整 |
| 科研方法能够迁移 | 源任务经验更新后，在独立目标任务上优于冻结对照 | 同一题继续调试，或多看了答案 |
| 更新机制得到改善 | 新旧 updater 从同一起点、相同反馈与预算产生的后代，在新任务上有差异 | 新 Scientist 直接答题更好 |
| 持续递归改善 | 多代、多独立运行中重复出现上述效果，且未靠扩大资源 | 一次正结果、一次更快达到阈值 |

项目当前首先需要建立第二级证据，同时把第三级的测试接口准备好。

### 2.1 AIDE² ignition 的正确读法

AIDE² §3.6、pp.10–11 的比较有两个独立分支：二者都从同一个内层 AIDE47 开始，仅外层分别使用 AIDE47 和人工开发的 AIDEhuman；每组 3 个随机种子、50 步。图 7 的平均终点为 0.780 与 0.782。治疗组较早进入最终分数区间，但作者明确认为证据不足，不能断言其自我改进更高效。

这比“新版本优于旧版本”多了一层因果问题：**谁更擅长把相同研究者继续改好？** 本项目应继承同一起点和同预算的比较，不继承“点火必然成功”的预期。

还需保留三项限制：pp.13 的讨论说明两层噪声会叠加；p.10 的一个“稳健性”改动实际没有改变候选排序，机制说明不能只看代码名；p.24 的表 2 显示外部评测有的以费用、有的以步数为主约束，不能把所有结果概括成统一的总成本比较。

AIDE² 原文表述比早期官方博客更适合引用；例如正式论文 p.8 的 reward-hacking 数字为 55%→32%，不应混入博客的旧数字。这些工程基准也没有直接测量科学问题价值或机制识别。

### 2.2 NeuroWeaver 和 AutoScientists 的边界

NeuroWeaver p.7 使用 200 次迭代、并行度 3，并报告约 20 美元 API 成本；该数字不等于完整训练搜索的总成本。p.4 的目标式写到 test utility，而 p.7 的文字未充分交代搜索反馈与最终测试的访问边界；这是需要源码核查的报告歧义，不能仅凭公式指控测试泄漏，也不能照搬为本项目协议。

AutoScientists p.10 承认相较单 Agent 使用更多 LLM tokens，主要匹配实验计算预算；p.23 还报告队伍扩大到 14 人时三个任务均较各自最佳队伍退化。因此，先采用少量角色和共享记录，不把“多 Agent”本身当创新或收益来源。

AutoScientists pp.21–22 的噪声门控、失败目录与后续提案协议值得借鉴；但其两次种子确认是经验规则，不能直接转写成多轮自适应搜索具有总体错误率保证。其 p.31 也明确指出单条改进链没有验证修改次序的交互效应。

## 3. 相关一手研究对创新定位的约束

本轮打开并核查了以下作者论文或项目页；这些是研究依据，不是本项目已验证的能力。

| 工作与位置 | 对方案的实际影响 |
| --- | --- |
| [NeuroAct](https://arxiv.org/html/2610.25211v1)，§3.1–3.2、§4.2、附录 E.3 | 直接相关的新工作：已提出 EEG 证据驱动内环、条件经验的提炼/迁移/修订外环。其 PhysioMI→BCIC-IV-2a 实验报告有/无经验差异。故“双循环＋EEG＋经验”本身不足以构成新颖性；其相关表格不能替代同起点 updater 比较 |
| [EvoScientist](https://arxiv.org/html/2603.08127)，§3.5、§5 | 将研究与工程经验写入持久记忆，评估提案与执行表现。仅做“轨迹→记忆→更好输出”必须与这类方法比较 |
| [GEPA](https://arxiv.org/abs/2507.19457v2) | 用执行轨迹反思、产生提示修改、保留互补候选；适合作为预算较小的固定 updater 基线，不能把提示优化自动称为 ignition |
| [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954v3) | 将 Agent 代码作为候选并保留多条谱系。可借鉴版本化与回退；编码成绩提升仍是科研方法提升的代理 |
| [HyperAgents](https://arxiv.org/html/2603.19461v1)，§3、§5.2 | 显式区分 task agent 与 meta agent，并允许后者修改；以固定 meta agent 产生后代的 improvement@k 衡量改进能力。它说明非编码领域不能假设“会做任务”自然等于“会改进自己” |
| [FIRE-Bench](https://firebench.github.io/)，Methodology | 将论文分成研究问题树，再将报告分成可验证主张；适合构造可审计的科学任务，但原论文结论只能在数据/模型/协议匹配时作为参考 |
| [SGM](https://arxiv.org/html/2510.10232v1)，§3、§5.1 | 将候选产生与统计接受门控分开；提示多轮反复选择需要累计错误控制。其保证依赖采样等假设，不能给少量 EEG 任务套上公式就宣称成立 |

推荐的差异化问题是：**在固定信息、计算和评价规则下，来自真实 EEG 研究轨迹的方法更新，能否提高可复验的科学判断；而更新机制本身能否继续变好？**

这比仅比较下游准确率更贴近 cx 的目标。NeuroAct 等工作应进入方法与对照选择；目前没有足够依据声称本项目首次实现 EEG 双循环、自进化或 RSI。

## 5. 精确定义改进对象

将一个研究者版本记为 `Scientist = (P, K, U, H)`，每项都有实际文件及哈希：

- `P`：研究决策策略，例如竞争解释、实验优先级、停止/转向、解释纪律。
- `K`：有触发条件、支持与反证的可复用方法经验；领域事实另存为所有条件共享的 `D`。
- `U`：从允许轨迹中诊断失误、提出/合并/淘汰策略修改的更新机制。
- `H`：调用、上下文、工具和角色编排的实现。首个试点只开放少量明确接口，不允许任意重写全部运行器。

冻结 LLM 版本、温度/采样设置、原始工具能力、数据与模型权重、评价器和预算执行器。策略可以选择调用何种工具；不能增加一组独有的隐藏计算能力。

可演化的内容优先为 `P/K/U` 的文本规则与有限结构配置；之后再允许 H 中的候选排序、上下文压缩或实验队列代码。模型权重更新暂不列入试点。

评价器、隐藏答案、分割、成本计量、权限与原始数据不在可编辑集合。科学工具的普通修复由 Builder 统一发布并重启新协议版本；不能把只给一组的环境修复计入其能力提升。

必须提供两个可审计的行为入口：`研究一个科学问题` 与 `根据轨迹提出研究者修改`。两者可使用同一模型和通用研究策略，但角色输入不同。如果更新过程始终由不变的外部 Distiller 完成，最多得到固定 updater 下的自改进，尚未检验 updater gain。

| 任务家族 | 示例研究问题 | 有意义的竞争解释与检查 |
| --- | --- | --- |
| 表示与读出 | 跨被试表现下降来自可恢复信息不足，还是读出/校准不适配？ | 冻结表示、匹配读出容量、适配样本与评价样本分开；全参微调不能作为“只换读出” |
| 表征与预测依赖 | 可恢复 EEG 属性是否对当前预测提供特殊贡献？ | 干预后残余探针、秩/强度匹配损坏对照；工具无法识别时允许结论受限 |
| 输入与泛化 | 改变通道或归一化后的提升来自信号保留还是身份/采集信息？ | 被试级分割、合法预处理、元数据/透明特征对照，不将采集因素说成神经机制 |
| 数据与目标交互 | 增加数据为何没有改善迁移？ | 未来在有授权算力时做 dataset×objective/适配因子设计，区分数据价值、优化和读出 |

本窗口已完成“表征与预测依赖”家族的EEGMAT开发与EEGMMIDB目标对照，但Actor只覆盖Q1。“表示与读出”的Builder参考与六份Actor候选均已完成数值审计，四份最终报告完成、两份因后端中断缺失。其200维固定均值池化表示限定了可裁决范围；缓存分析不能支持其他池化、基础模型重训、跨会话或生理因果主张。不为凑覆盖临时训练新FM。

后续优先补的是两类不同缺口，而不是继续重复当前读出表。第一类仍围绕预测依赖：让研究者实际比较定向干预与匹配的一般损坏，并检查修改后目标信息是否仍可读出。它直接对应第一组六次都未执行的部分；任务必须允许有效负结果，并防止把任意性能下降解释为目标属性被使用。

第二类检验信息是否在池化时丢失：在相同冻结token、训练人群和选择预算下，比较均值、重复均值与保留token的读出。[Beyond Accuracy §4.5/附录J](https://arxiv.org/html/2605.17562v2#A10)已有明确的头结构和参数数目匹配，因此普通池化对比本身不是新发现。一个更具体的检查是有效正则化和优化是否匹配：对简单线性模型，重复同一均值向量不增加信息，但相同数值的L2系数不一定意味着相同约束。这是待验证的设计推理，不是对该论文实现的定罪，也不是本轮已经做出的结果。

具体先做线性对照校准：在损失归一化、训练拟合的缩放、截距处理相同且优化收敛时，将均值向量重复k次，其有效L2约束变为原系数的1/k。因此匹配时应令`λ_repeat = k × λ_mean`，或者把重复输入除以`√k`并保持同一λ。该推导只适用于标准线性L2目标，不能直接推广到AdamW、早停或非线性头。校准通过后，再比较“原均值”与“原均值＋各token偏离均值的零和成分”，保留均值块尺度和惩罚，对新增成分单独正则化。这样逐步检查是否有额外的可利用预测效用，不把一次性能差异说成已证明信息论意义的信息丢失。当前42名测试被试已查看，只能作后续开发材料，确认阶段须使用新的独立评价任务或人群。

两类题可以检验不同科研能力：前者要求把“能读出”和“预测依赖”分开，后者要求把“新增信息”和“训练规则变化”分开。下一轮方法修改应从允许的开发失败中提出，在独立选择题上比较，再到未用于选题/改方法的评价题上冻结测试。本轮已经查看的结果不能重新包装成全新的未知答案；每题还应公开足以判断比较条件的模型头、训练人群和预处理来源。

外环也有一个需要单独检验的设计问题：第一组机器结束条件允许只完成Q1，来源轨迹也只有Q1，而我们希望改进的是完整研究闭环。当前负结果尚不能区分“方法规则帮助不大”“来源经验不足”与“任务结束条件没有促使研究者补做关键实验”。下一轮应在开发阶段比较明确的证据覆盖反馈与现有结束条件，并保持最终题独立；不能事后修改本轮判分，把合法的Q1结题改记为违规。

开发阶段可用一个2×2比较拆开方法规则与结束反馈：固定领域知识，分别开关方法规则与证据覆盖反馈；资源、科学接口和允许结论保持一致。覆盖反馈只说明哪些证据尚缺，不要求得到正结果。这样可以观察方法规则本身、结束机制和二者交互，而不是一次同时改掉全部条件。来源经验是否足够仍需另行检验。候选先在独立选择题V上确定，再以统一结束规则冻结到最终题T；这一步完成前不跳到ignition。

源任务集 `A`、候选选择集 `V`、最终评价集 `T` 按研究问题/数据来源分离；任务内再分别冻结 train/validation/test。两层划分不可混称。

第一层迁移用 `T_transfer`，第二层 ignition 用另一个 `T_ignition`；下文的 T 指各自阶段的封存集。若研究者看过第一层结果并据此设计 U1，第一层题就成为第二层的开发历史，不能再次充当独立终测。

Builder 已分析某题不妨碍它作为受测 Actor 的封存题，但报告必须说明它是“Actor 未见”；不能说成所有人都未见。相邻层、相邻特征、随机种子或原题换措辞只算同域变体。

## 7. 第一层试验：检验方法迁移

1. 从 A 的真实轨迹释放允许的开发材料，包含失败、决定与成本；删除最终测试答案、参考脚本和禁见材料。
2. 固定共享领域事实 D。所有条件得到相同数据描述、工具、公共文献范围和领域证据。
3. 用初始 updater U0 产生候选 P/K 修改，记录原规则、失误证据、适用范围、预期行为变化与反例。
4. 仅用 A/V 选择候选并冻结 Scientist1；最终 T 完成前不修改它。
5. 在 T 上配对运行初始与新研究者，顺序随机或交错，保留全部失败；每次独立上下文、固定相同资源额度。

第一组试点已经比较原版、Knowledge-only、Knowledge+method三条件，主对比为相同知识下的方法增量。以下对照中仅Knowledge-only已执行，其余是后续选择：

| 对照 | 控制的替代解释 |
| --- | --- |
| Knowledge-only | 共享相同 EEG 事实与结果摘要，但不提供学习到的方法规则，排除“知道更多答案” |
| 等长一般研究提醒 | 控制额外文本、注意力与提醒效应；长度匹配不足以证明信息量相同 |
| 原始轨迹/直接摘要 | 区分蒸馏机制与简单增加记忆；同样受上下文及总成本限制 |
| 固定专家规则或固定 GEPA 式 updater | 检查自动更新是否超过一套强而静态的方法 |

“没有规则”不能意味着没有 API 说明或不能使用必要工具。试点样本少时，只报告已做的对照，不把缺少 knowledge-only 的效果解释为纯方法收益。

## 8. 第二层试验：同起点 ignition

这是尚未准入、尚未执行的核心协议，与第二组读出Actor对照不同。把上一阶段产生的 updater 候选记为 U1；在验证前，它只是候选，不能因来自较好的 Scientist 就称为“更好 updater”。U1 可由 U0 对源轨迹反思后提出，或来自明确开放 U 的版本搜索；来源必须可追踪。

冻结同一个起始研究者 S*、同一允许反馈包 F、同一候选选择集 V。比较：

```text
旧更新机制 U0 + (S*, F, V, 预算 B) → 后代集合 → 按 V 选定 C0
新更新机制 U1 + (S*, F, V, 预算 B) → 后代集合 → 按 V 选定 C1
                                      冻结后 → 独立 T 评价 C0/C1
```

两个分支中的起始 P/K/H 与领域事实完全相同；只替换 U。U 在一次 ignition 分支内保持冻结，后代可修改集合相同。这样测的是更新机制产生后代的能力，避免“新组起点已经更强”的混淆。

若采用 AIDE² 式整位研究者晋升，可另外比较 Scientist0/Scientist1 在相同 meta 角色包装下改进 S*；须逐项列明哪些策略随晋升变化。该比较不能与“只替换 U”的消融混为一谈。

定义同预算的描述性效应：`Δignition = Q_T(C1) - Q_T(C0)`。两个分支都未超过 S* 时，即便相对差值为正，也不能说成功产生了更好研究者。

记录候选数、可运行率、拒绝原因、验证成本、最终后代质量及全过程质量—成本曲线。每个预算检查点的候选只能按 V 选择，再由外部在 T 上评估；不能按 T 挑最佳后代或回头改阈值。

同时控制三类资源：相同候选数上限；相同每次内层 episode 额度；相同外层总成本额度。报告谁先触及哪个上限。只匹配次数却给新 updater 更多推理 tokens，不能解释成更高研究效率。

配对复用相同底层数据划分和实验随机数以降低比较噪声；LLM 轨迹仍独立。两分支不得读取对方当轮提案或产物。一次 outer run 内多个候选高度相关，不当作多个独立 ignition 重复。

这是与信息收益最直接的区分：D/F/S*/工具相同，更新过程不同。第一层证明“学到的策略有没有用”；第二层证明“产生策略的方法有没有变好”，两项结论独立报告。

## 9. 评价：先证据有效，再讨论质量与效率

第一组按目标前冻结的[评价规约](method-transfer-evaluation.md)，分别报告提交覆盖向量N和有效证据向量V；二者均按`(Q1/24, Q2/2, Q3残余探针/2)`逐项展示，不用0–3概览或总分掩盖缺项。Q1要求仅用训练材料拟合、验证选择、封存测试读出及真正随机标签重新拟合的空对照；Q2要求同一冻结下游计算的完整张量干预和匹配损坏对照；Q3要求在改变后的训练表示上重新拟合残余读出，不能称为原论文closure。每项必须有实际产物、来源审核及关键数值重放，提案文字不计。正、负及无法区分解释的结果均按证据判定，不按结论方向奖励。第二组读出任务使用其自身冻结的有效性与判别标准，不沿用Q1覆盖数充当新题成绩。

次要结果为主张层面的支持/矛盾/证据不足/未覆盖/条件不匹配、参考覆盖、越界结论、执行失败及实际成本。论文原结论只在条件匹配时直接比较；改编任务用当前环境参考，未覆盖的合理属性另做独立核验。比较组标签在主张审核输入中隐藏，保留审阅可能从报告风格推测处理组的局限。只有一个独立目标题时，不对多次重启做跨任务显著性推断。

不用一个未经校准的 scientific-taste 总分作为唯一目标。冻结任务内的评分细则，先做有效性门控，再记录以下向量：

- **有效性**：分割合法、实际执行、数值可重算、引用可定位、未读取禁见材料。严重失效不能以更高准确率抵偿。
- **判别力**：是否预先列出会导致不同结论的预测，并实际完成相应比较；不能按提案中假设条数计分。
- **证据支持的主张**：原子主张与产物对应；区分被支持、被削弱、尚不能识别，记录越界主张。
- **校准与更新**：实验前冻结方向/区间/可能结果；结果后是否按证据修订，负结果是否仍有信息。
- **成本与人工依赖**：所有调用、失败实验、验证、CPU/GPU 用量、人工修改分钟数；分别报告研究成本和开发成本。

研究任务的正向结果可以是排除解释，也可以是有效证明当前设计不足以区分解释；“没有显著差异”本身既不证明等价，也不自动获得有信息的负结果评分。

外环如需标量选择，使用事先登记的窄目标，例如“通过有效性门控的任务中，完成预定判别要求的比例”；其他维度作为不可恶化条件并完整公开。不要奖励堆主张、选容易题或只报告预测正确的实验。

人工盲审者看去条件标签的报告和证据；LLM 审阅可辅助定位错误，不能独立裁定科学正确。超出参考但可重验的发现应单列裁决，不能因未复述参考答案一律判错。

若暂时没有领域专家，可先只评价数值有效性、可识别的设计缺陷和预登记的狭义判断。不能把 Builder 自评或 LLM 喜好分写成专家确认的 scientific taste；新颖性与研究价值保留待审。

## 10. 污染、反复选择与可重放

- Actor、updater、选择评价器和最终评价器拥有独立允许材料清单。隔离靠进程/目录/工具权限及实际访问记录验证，不能只依赖提示词。
- 目标论文的完整方法、结论、答案脚本及旧终测报告不可进入 Actor/updater；允许联网时需冻结检索范围，并记录访问。无法排除模型预训练记忆，须如实报告。
- 策略正文、实际模型请求、工具输出、源码差异、依赖、数据/缓存身份、种子、预测时间戳、所有候选与拒绝记录均可追溯。
- V 被反复用于选择后就是开发资料，即使其底层标签对 Actor 隐藏；只有从不向更新过程反馈的 T 才能支持最终泛化判断。
- 规则携带源数据结论或目标任务特征时要标记其知识成分；不能把答案换成“建议”后视为纯方法。
- 独立重放包含关键数值重算、规则注入核验、候选哈希核验和越权检查。重放已记录代码不等于复现随机 LLM 轨迹，二者分开报告。
- 多候选、多代扩展时采用独立确认批次或事先设计的序贯门控；不能用一次幸运高分直接形成不可逆的长谱系。

## 11. 后续预算模板：迁移证据优先，ignition设准入门

以下是未来窗口的预算模板，不是已测吞吐，不构成新运行授权。本轮原8小时停止新增实验、9小时截止的记录保留，后续安排以开头所述用户授权追加为准。未来正式开始前冻结协议与实测episode耗时；不在一个窗口里强行完成两项都缺乏有效评价的结果。

| 时间段 | 主要工作 | 必须留下的产物 |
| --- | --- | --- |
| 0–1.5 小时 | 审计 A 的真实开发释放包；冻结 V/T、工具能力、角色权限和实际可用算力；校准一个短 episode | 材料清单、版本哈希、资源表、任务与评分协议、实际耗时 |
| 1.5–2.5 小时 | U0 提取少量有证据的方法候选；选择并冻结 Scientist1；记录 U1 是否已存在且可运行 | 可读策略差异、触发/反例、来源、注入证据；未实现的 updater 明确留空 |
| 2.5–6.5 小时 | 默认完成独立真实目标任务上的两次配对；每组额度相同、顺序交错 | 全轨迹、预注册预测、实验、报告、失败与资源账本 |
| 6.5–8 小时 | 关键数值重放与盲化审核；如条件允许做对应反例检查 | 分项结果、有效性/污染检查、知识与方法成分说明 |
| 8–9 小时 | 汇总正/负结果、冻结候选、写明确下一步 | 结论边界、可恢复入口、尚缺资源/任务/重复 |

**微型 ignition 的准入门**：第一层链条已有效完成；U0/U1 均可执行；两个 V 任务和至少一个独立 T 已冻结；按实际耗时能完成双方全部候选、终测及至少 90 分钟审计。门未通过，保留协议，不启动不完整对比。

该门可以在后续窗口开始前由已完成的迁移试点满足。当前缺口较多时，九小时合理交付是第一层完整证据与第二层可运行准备，不能承诺同时完成可信 ignition。

若门通过，可用一个独立 outer replicate、每组至多两个候选、每候选相同两个 V 任务的微型版本，替换上述执行段的一部分；双方从同一 S* 起步，最终后代都评估 T。应明确这是可行性试点，不与完整多重复试验共用结论。

冻结资源表至少填写：模型/采样、每 episode token 与费用上限、CPU 秒/内存、最大实验数、外层总额度、超时和故障处理。具体数值由校准决定后统一锁定，不能分别按每组速度调整。GPU 默认仍为零，除非另有明确分配。

无法同时完成两个科学家条件时，优先减少事先选定的任务范围或停止新 pair；不能只汇报完成/成功的一组。服务故障、工具故障和科学错误分别记账；预登记共同的重试规则。

## 12. 扩展路线与停止规则

第一阶段完成真实经验迁移、规则生效检查和知识对照。第二阶段增加多个问题家族与独立 outer replicates，执行同起点 U0/U1 比较；复用计算缓存降低成本，但终测保持独立。第三阶段才允许受限 harness 代码演化，并做逐组件回退与策略/工具消融。第四阶段扩大到预训练数据、目标与适配交互，检验更开放问题上的科学价值和专家依赖。

多重复规模按试点任务间与运行间方差、最小有用差异和可承担预算确定；不要把“3 seeds”当万能显著性保障。统计单位首先是独立科学任务与 outer run，不能把同一被试的窗口或一条谱系的候选当独立样本。

停止新候选的条件：预算或预留审计时间不足；测试泄漏；两组资源/工具不同；评分器失效；必要干预无法执行；唯一“提升”来自规则改写评分或选择容易题。有效失败保留，基础设施失败单列，不通过偷偷补算修成正结果。

结果解释按以下规则：

| 观察 | 合法结论 |
| --- | --- |
| 策略未进入实际请求 | 干预未实现，不能评价方法有效性 |
| Scientist1 更好，但 knowledge-only 同样好 | 目前不能排除信息收益 |
| 选题/结论更好，预测分数没有提高 | 可报告科学过程改善，不能宣称模型性能提升 |
| V 提升、T 不提升 | 选择过拟合或迁移失败的证据，不追加 T 调整 |
| U1 后代没有优于 U0 后代 | 本协议下未观察到 updater 优势；不是宣告所有 RSI 不可能 |
| 一次微型 ignition 差值为正 | 候选机制与可行性信号，尚不能证明稳定 ignition |
| 多任务、多重复中同起点后代稳定改善 | 支持所测范围内更新机制更有效；持续加速仍需更多代证据 |

最有价值的交付不是“又得到一张更高分表”，而是一条可复验的链：真实科研失误→方法修改→新题行为变化→科学证据质量→同反馈下下一代修改的收益。任何尚未闭合的箭头都应保留为未完成项。
