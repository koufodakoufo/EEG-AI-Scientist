# 论文工作流试验收尾

本计划依据用户 2026-11-16 确认的收尾范围执行；不重新打开无边界的系统扩建。

**结束点：**完成现有 LEACE 改编 EEG 题的独立研究、数值复核和论文对照；再用 BrainPEC 已有 Q1 报告回顾性检查同一入口，交付可审核结果和未完成项。

**实现：**复用 `paper prepare/freeze/compare`、残余恢复任务及火山云 CPU 执行器。原始冻结题包、历史运行和失败记录保持原样。新执行使用新的身份、期限和实际环境检查。论文答案不交给研究者。

## 工作和验收

- [ ] 执行准备：核查两个服务器、数据与源码身份、研究者初始上下文和公共输入边界。仅修复阻碍本试验的实际故障；检查当前通道，不沿用已过期准入。
- [ ] EEG 实验：独立作者实现 affine/flexible 读出，完成两个公开拟合、验证选择、一次锁定测试及报告。遵守四线程、12 GiB、六上下文及每次运行事先登记的期限；一次前瞻时限校准见下，旧期限不改写。
- [ ] 证据核验：两个重放及独立源码/数值审核；不把计算结束或自述当成可信结论。保留负结果、失败和缺失。
- [ ] LEACE 对照：完整原报告走统一比较入口。论文理论条件与当前 EEG 条件分别记录；不把自己的预期当论文实证答案。科学结论和流程通过分别判定。
- [ ] BrainPEC 复用：固定一份完整历史 Q1 报告及其来源，使用同一入口制题、审阅和比较。明确回顾性性质、条件差异和 Q2/Q3 未完成，不宣称新盲测或整篇复现。
- [ ] 收尾：结果写入现有研究报告，简化 README 当前入口，更新 BrainPEC 完成表，必要回归、Git 同步、私有证据备份及恢复校验。

## 边界与失败处理

新研究运行最多一次主要尝试及一次有明确工程原因的修复后重新尝试；每次独立登记，失败不覆盖，不因结果不好重跑。比较器若确实无法产生可比结论，保留原因并报告评价缺口，不伪造通过。未完成的科研步骤不能作为负结果。

第一题只有六名测试参与者，且项目已见过这些数据；属于探索性研究。初始 LEACE 参考是连续目标与最小二乘论述；本次审阅通过的 r03 参考为第 7 节的适用范围与猜想，不能当作 EEG 实证答案。第二案例为历史材料重分析。两案例不足以证明任意论文通用性，更不构成科研能力增益或 RSI。

## 资源与检查重点

火山云执行科学计算；本地协调模型会话，NCC 控制/复核/备份。使用已有缓存，不计划 GPU 或骨干训练。实际可用资源须重新检查。预计 12–24 小时推进，环境故障可能延长；时间估算不代替每次运行预算。

重点检查：过期会话与日期路径、答案泄漏、测试前锁定、论文条件不匹配、重放与作者原结果不一致。若需改代码，先复现故障并增加针对性检查，再由另一作者复核；不为凑覆盖率增加测试。

运行记录置于 `.local/research-renewal/phase-completion-v1/`，不提交私有参考、认证、数据或模型权重。

## 执行决定

- 初始上下文检查观测到当前原生模型是 `gpt-6-astra / ultra`，旧准备登记的是 `gpt-6.1-sol / high`。新运行明确采用实际身份；不进行跨模型能力增益比较。旧身份和旧记录不修改。
- 原生编码入口原先硬编码旧模型；仅新增经过实际上下文检查的身份，并让登记和执行沿用同一个配置值。历史原生运行路径不变；实际上下文仍须逐次与登记身份匹配。
- LEACE 论文工作流的旧政策包含旧模型身份，不能直接改写。使用有父版本关联的 r02，重新制题、抽取和审阅；科学资源条件保持一致，重新审阅后再交给研究者。
- r02 题包审阅发现检查顺序错误，保留拒绝记录；r03 根据实际接口澄清顺序后重新制题、抽取并通过审阅。论文参考改为第 7 节的范围讨论与猜想，不能当作 EEG 实证答案。
- 本次存储余量先验改为 8 GiB，保留两台机器合计 1 GiB 研究产物上限及运行中检查；未移动或删除旧成果。
- 执行 r01 在 NCC 部署前因 Python 3.10 缺少辅助程序使用的哈希函数失败；执行 r02 在控制器启动时因另一个旧模型固定检查失败。两次都没有研究者调用、拟合或科学评分，旧目录、截止时间和日志保持原样。
- 启动失败说明原“一次工程修复”估计不足。现明确补一次启动前修复及合成完整启动验证，再安排 r03；不是重跑科学结果。首次实际科研仍使用原有 2700 秒、六上下文、两个拟合和一次锁定测试，不因结果不佳追加运行。任何后续故障都必须单独说明，不能将缺失结果算为负结果。
- 本地网络切换后无法连接 NCC 校园网地址。控制器迁到火山云个人目录，与 Docker 工作进程使用不同目录；本地通过公网管理，控制器通过已核验主机密钥的本机 SSH 连接工作进程。未修改网络配置。存储按同一个物理研究目录计一次；原 NCC 成果保持原位。控制器原有最长 1800 秒的限制继续保留，2700 秒是整个试验及重放的总期限。
- 首次云端会话在题目释放前被审计拒绝：应用更新后 PowerShell 路径改变，旧检查只接受旧路径。会话未获准，拟合及科学作业均未开始。保留原冻结运行；新增当前实际观测路径的精确检查，与旧路径共用验证函数，仍拒绝未登记版本、额外参数和任意命令。新路径已用真实首条命令的本地前缀核验；这只证明兼容性，不补授旧会话资格。修复通过回归后，另登记新运行，沿用原科学预算和边界。
- cloud-r02 首个正式会话通过初始准入并读取任务，但 16 次合法网关调用后的最终收尾约为 246 秒，超过原定 240 秒。旧运行保留超时失败，零拟合、零科学评分；不事后接收其内容。现前瞻登记一次流程时限校准：六会话、每次最多 480 秒、整个试验 4200 秒、控制器 3600 秒，重放预留仍为 420 秒。旧配置默认值及旧登记不变。数据、方法约束、拟合/测试/重放次数、单作业资源上限均不变；论文题包另作预算修订并重新审阅。这是适配实际交互耗时的流程开发，不是同预算能力比较，不因 EEG 结果不佳追加尝试。
